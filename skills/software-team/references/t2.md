# T2 playbook

Read `references/rules.md` (the charter) before PLAN. The T1 playbook's PLAN shape and
convergence cap apply, with these additions.

## Gates before BUILD

- **Researcher is mandatory** — skip only a fully-specified static change (one config
  value, a verbatim swap) whose current-state, blast-radius, and rollback facts are
  already evidenced in the conversation. A migration, prod-config, destructive, or
  access-control change never skips it, however exact the diff.
- **Explicit human approval of the plan before BUILD — always.** The confirmation
  rule's wait branch with no proceed-without-waiting case. Approval of one revision
  never carries to the next; BUILD starts only on explicit confirmation of the current
  version.
- **Opus floor on every spawn** (`references/model-routing.md`), one exception: a
  human-approved plan that fully specifies the diff and leaves the builder no judgment
  call may run its builder at sonnet — state the reason in `Context:`; every
  review/verify spawn stays at opus. Any doubt → opus.

## Fable gated review — the T2 review pass

There is no separate reviewer role — this Fable pass IS the T2 review. After BUILD, spawn **one** Fable review via
the Agent tool: `subagent_type: general-purpose`, `model: "fable"`. Read-only by
instruction — the Agent tool cannot strip tools from a general-purpose spawn, so its
prompt must state it never uses Write/Edit; this is instruction-enforced, not sandboxed.

Its prompt carries: the full integrated diff (every builder's changes together), the
**identical** `Acceptance criteria:` and `Out of scope:` lines, the 5-category
checklist (correctness, security, performance, impact, plan conformance),
and the demand for a verdict — **`APPROVED` or `CHANGES REQUIRED`, one evidence line
per category, findings tagged by category and severity**, the same anti-rubber-stamp
bar the verifier's `Mode: REVIEW` sets (`agents/verifier.md`). Advice-shaped output without a verdict is an incomplete
review — re-ask for the verdict.

- `CHANGES REQUIRED` routes back to BUILD like any review finding and counts toward
  the 3-round cap. After the fix, run **exactly one** more Fable pass over the updated
  diff — a bounded rerun, not a loop.
- N parallel builders still get one Fable pass over the combined diff — not N passes.
- Report a clean pass in one line; it is a gate, not a ceremony to narrate.
- It can share the read-only batch with the verifier and security-reviewer (all read
  the same finished diff).

## Security review

Spawn `software-team:security-reviewer` before DONE whenever the diff touches auth,
payments, PII, secrets, or a public API — a dedicated OWASP-class pass, separate from
Fable's one security checklist line.

## Done on T2

The Done gate's item 2 means: verifier `PASS`, Fable `APPROVED` (including its bounded
rerun if triggered), security-reviewer `CLEAR` where spawned — all recorded with
evidence. Any deploy runs via `software-team:deployer` only after the Fable verdict
clears.
