# Decisions

- 2026-08-20: Renamed `ai-software-team` to `software-team` and rebuilt it as a real subagent-orchestrator plugin (was a single-conversation role-play skill with no subagent spawning) — user wanted actual delegation, mirroring the `agent-office` plugin architecture, per fable-advisor consult.
- 2026-08-20: Keep `agent-office` published alongside `software-team` rather than deprecating it — user's explicit choice; the two skill descriptions must stay differentiated (software-team's is the always-delegate, zero-self-edit variant with a dedicated reviewer) to avoid trigger collision.
- 2026-08-20: Orchestrator spawns `software-team:builder` on every task that touches a project file, T0 included, rather than doing trivial edits inline — user's explicit choice, confirmed over the agent-office default of handling T0 in-context.
- 2026-08-20: Ported team-agent-workflow's guard_bash/guard_secrets/log_agent/pre_compact hooks as first-class plugin hooks (`hooks/hooks.json`); skipped guard_tier.py (path-heuristic T2 detection judged too noisy) and the project-vendored ground-truth doc templates (docs/product.md etc. — project-specific, not plugin material).
- 2026-08-20: Added `security-reviewer`, `documenter`, and `deployer` agents to reach full software-team role coverage (user request: "add agents covering every software role"). Reverses the earlier "no security-reviewer/documenter — routes to skills/verifier instead" stance from the initial rebuild, since a first-party agent doesn't depend on an external skill being installed and gives DONE a concrete, mandatory spawn to point at. Deliberately did NOT add `architect` — PLAN stays with the orchestrator, and the `fable-advisor` path already covers top-tier architecture consults; a separate architect agent would duplicate both.
- 2026-08-20: Added parallel-spawn guidance (disjoint-`Files:` test), within-tier complexity-based model escalation (tier sets a floor, complexity can push a spawn's model up but never down or past T2's opus), and a `designer` agent (UI/UX — DESIGN mode spec before PLAN, REVIEW mode audit before DONE). User confirmed "designer" means UI/UX, not a meta-agent that generates other agent files, via explicit choice. Model-routing philosophy line changed from "match to cost of mistake, not size of task" to "primarily to cost of mistake, secondarily to complexity" — a deliberate softening of the earlier stance, not an oversight.
- 2026-08-20: Studied `wayfinder` (a separate installed skill: shared decision-ticket map on an issue tracker for work too big for one session — destination/fork/ratification/fog-of-war vocabulary, human-invoked by design) in full per user request, and added `## When PLAN doesn't fit one session` to PLAN. Deliberately did NOT reimplement wayfinder's map/ticket/frontier machinery inside software-team (that would be a second, divergence-prone copy of an already-installed skill) — instead PLAN now sizes itself before drafting and, when oversized, recommends the human invoke `/wayfinder` directly, handing off a draft destination/forks/fog so charting doesn't start cold. Small forks (1-2, resolvable inline) stay in PLAN's existing fork-question flow unchanged.
- 2026-08-20: Reversed the previous entry's `/wayfinder` hand-off per explicit user request ("no external referent skills") — the plugin must not assume any other skill is installed. Replaced with a self-contained Phase Map: PLAN still sizes itself and refuses to draft an oversized monolithic plan, but the escalation path is now an in-repo phase breakdown (own artifact, closed via the existing `docs/decisions.md` mechanism) instead of naming an external skill. Also removed the `superpowers:systematic-debugging`/`superpowers:brainstorming` routing rows (replaced with self-contained researcher-spawn / ask-the-human equivalents), the `fable-advisor` skill reference in Model routing (replaced with a direct one-shot Fable `Agent` spawn description), and the `security-review`/`secure-code-guardian` external fallback in Definition of done (security-reviewer is the plugin's own first-party agent, no fallback needed). Kept the `agent-office` comparison in the description/README — it's not a functional dependency, just differentiating text for skill-router disambiguation. Also reset `plugin.json` version to `0.1.0` (first published version, not `1.0.0`) and expanded README's Install section into explicit Install/Verify/Update steps.
- 2026-08-20: User flagged that the previous entry's one-line replacements for `superpowers:systematic-debugging` and `superpowers:brainstorming` were functionally thinner than what they replaced, not just differently-sourced — closing the external referent isn't done if the capability regresses. Added two full sections: `## Debugging before PLAN` (reproduce -> trace -> hypothesize-and-falsify -> cross-reference, before any fix gets planned) and `## Unsettled requirements before PLAN` (state current understanding -> surface every open question as an explicit fork with options/recommendation/cost -> stop and wait, never guess a destination speculatively). Also expanded the one-line Fable mention in Model routing into a `**Consulting Fable**` protocol (gate criteria, self-contained brief, no-edit-tools spawn, plan-is-advice-not-authority, ~2-call budget) so the removed `fable-advisor` skill's discipline is actually preserved in-line, not just referenced away.
- 2026-08-20: Functional test of "Debugging before PLAN" against a race-condition bug (intermittent double-charge on checkout double-submit) surfaced a real gap, not a cosmetic one: `software-team:researcher` was Read/Grep/Glob/WebFetch/WebSearch only, no execution, so it structurally could not do Reproduce (needs to fire real requests) or Hypothesize-then-falsify (needs to add logging and rerun) for anything beyond trivial deterministic bugs — the section's own "(or do them yourself if trivial)" escape hatch doesn't cover the exact non-trivial case debugging methodology exists for. Fixed by adding `Bash` to researcher's tools (diagnostic/reproduction only — contract explicitly forbids editing tracked files, throwaway repro scripts go outside the repo), and adding hit-rate-based reproduction/falsification guidance to the Debugging section for intermittent/timing bugs (a debugger break is explicitly wrong for a race — it changes the timing window being observed). Also fixed the smaller gap the same test found: the spawn template didn't cover researcher's field shape (no Verify with:/Load skill:, Acceptance criteria: means "what findings must establish" not a build outcome) — added a note. A second test on "Unsettled requirements before PLAN" (vague "better notifications" request) passed cleanly but suggested checking whether the current directory is even the right target codebase before drafting product-shaped forks — added as a one-line addition to step 1.
- 2026-08-20: Added `software-team:tdd-builder` (10th agent) — same contract as the general builder, but strictly red (a failing test confirmed to fail for the right reason) -> green (minimum code to pass) -> refactor (tests kept green throughout) per acceptance criterion, reporting the actual red/green trail as evidence. Spawned instead of the general builder whenever the plan calls for TDD, or the task is a bug fix (the regression test from "Debugging before PLAN" is its first red step — wired directly into that section). Verified via a live spawn on a small fizzbuzz task: the RED step on criterion 3 caught a real implementation bug mid-loop (a shadowed branch) before any "final" code was written, confirming tests actually drove the code rather than being retrofitted.
- 2026-08-20: Replaced the tier-only "Model routing" floor table with a difficulty-first scale per user request ("don't fix the model — choose by task difficulty"): mechanical (rename, typo/text fix) -> Haiku, simple/well-understood -> Sonnet, complex/hard (3+ interacting files, concurrency, a real judgment call, a failed round, or any T2 work) -> Opus. Risk tier from Step 2 still sets a floor the difficulty pick can't undercut (T0->Haiku, T1->Sonnet, T2->Opus floor); the stronger of the two wins per spawn. New hard rule: every opus-tier spawn — T2-floor or complexity-escalated — now gets a **mandatory** one-shot Fable review of the finished diff before DONE (separate from the existing optional pre-BUILD Fable planning consult, which stays gated/optional). Wired into Definition of done as criterion 10.
- 2026-08-20: Installed the Claude Code plugin locally on this machine (`claude plugin marketplace add`/`install`, v0.1.0, confirmed via `claude plugin list`/`details` — 9 agents, 4 hooks, 3 skills/commands, no errors). Also ported the whole design to a Gemini CLI extension at `gemini-extension/` (gemini-extension.json + agents/*.md + skills/software-team/SKILL.md + references/*.md + commands/*.toml + hooks/hooks.json+*.py), per user request to install this skill for Gemini too. Gemini CLI (v0.44.0, installed on this machine) turned out to have a near-identical extension model — same `agents/`/`skills/`/`commands/`/`hooks/` directory convention, same SKILL.md frontmatter format, its own `gemini hooks migrate --from-claude` tool (confirmed PreToolUse->BeforeTool, `$CLAUDE_PROJECT_DIR`->`$GEMINI_PROJECT_DIR`, matcher name changes) and a documented subagent frontmatter schema (name/description/kind/tools/model) close enough to Claude's that a faithful 1:1 port was possible rather than a reinterpretation. Tool names mapped (Read->read_file, Write->write_file, Edit->replace, Bash->run_shell_command, Glob->glob, Grep->grep_search, WebFetch->web_fetch, WebSearch->google_web_search, Skill->activate_skill); model tier language (Haiku/Sonnet/Opus/Fable) deliberately left generic (cheapest/fastest, balanced, most capable, extended-reasoning) rather than pinned to a dated Gemini model string. Installed and verified via Gemini's own tooling: `gemini extensions validate` passed, `gemini extensions install --consent` succeeded, `gemini extensions list`/`gemini skills list` confirm all 9 agents + the skill + 2 commands registered at `~/.gemini/extensions/software-team/`. Disclosed gap: this machine's Gemini CLI account could not authenticate (free-tier ineligibility error), so the three hook scripts' exact JSON payload field names were never confirmed by a live tool-call/subagent-spawn — event *names* are doc-confirmed (BeforeTool, BeforeAgent/AfterAgent chosen over the Claude-echoed but undocumented SubagentStart/SubagentStop, PreCompress) but the hooks parse several plausible field-name variants defensively rather than assuming one. Also chose BeforeAgent/AfterAgent over SubagentStart/SubagentStop specifically because Gemini's official hooks-events doc table lists the former, not the latter — the migrate tool's verbatim passthrough of SubagentStart looked like an unrecognized-key fallback, not confirmation it's a real event.
- 2026-08-20: Investigated `agy` (v1.1.16, a separate multi-backend CLI at `AppData/Local/agy/bin/agy` with working Gemini/Claude/GPT-OSS login on this machine) as a way to live-test the plugin now that plain `gemini` CLI couldn't authenticate. `agy plugin import "D:/projects/ai-software-team"` auto-detected and staged the Claude-format plugin correctly (9 agents, 1 skill, 2 commands, 1 hooks file; `config.json` shows `"software-team": {"enabled": true}`), and its generated `hooks.json` kept Claude's exact event/matcher names and `${CLAUDE_PLUGIN_ROOT}` verbatim — promising. But live testing found the import does not actually wire into a running session: a real `git push --force` and a real `.env` read both executed unblocked (guard_bash.py/guard_secrets.py never fired), `agy agents`/`--agent builder` show no registered agents and no persona change, and no `.claude/state/agent-log.jsonl` was ever created. Along the way, fixed a real but unrelated bug: `~/.gemini/config/skills.json` (agy's own generated file) had a UTF-8 BOM that made agy's own JSON parser fail to read it back (`invalid character '\ufeff'` in the debug log) — stripped the BOM, confirmed the file parses now, but this did not fix the agents/hooks-not-loading issue (that file only points at the shared `~/.agents/skills` directory, unrelated to our plugin's own agents/hooks). Conclusion: `agy plugin import` currently stages files and marks config as enabled without functionally activating hooks or agents at runtime (v1.1.16) — a limitation/bug in `agy` itself, not in this repo's plugin files (which agy copied byte-for-byte correctly). Stopped investigating further per user request ("ok พอแค่นี้") rather than continuing to reverse-engineer a third-party closed tool.
