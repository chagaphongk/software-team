- 2026-08-20: Added parallel-spawn guidance (disjoint-`Files:` test), within-tier complexity-based model escalation (tier sets a floor, complexity can push a spawn's model up but never down or past T2's opus), and a `designer` agent (UI/UX — DESIGN mode spec before PLAN, REVIEW mode audit before DONE). User confirmed "designer" means UI/UX, not a meta-agent that generates other agent files, via explicit choice. - 2026-08-20: Studied `wayfinder` (a separate installed skill: shared decision-ticket map on an issue tracker for work too big for one session — destination/fork/ratification/fog-of-war vocabulary, human-invoked by design) in full per user request, and added `## When PLAN doesn't fit one session` to PLAN. Deliberately did NOT reimplement wayfinder's map/ticket/frontier machinery inside software-team (that would be a second, divergence-prone copy of an already-installed skill) — instead PLAN now sizes itself before drafting and, when oversized, recommends the human invoke `/wayfinder` directly, handing off a draft destination/forks/fog so charting doesn't start cold. - 2026-08-20: User flagged that the previous entry's one-line replacements for `superpowers:systematic-debugging` and `superpowers:brainstorming` were functionally thinner than what they replaced, not just differently-sourced — closing the external referent isn't done if the capability regresses. - 2026-08-20: Functional test of "Debugging before PLAN" against a race-condition bug (intermittent double-charge on checkout double-submit) surfaced a real gap, not a cosmetic one: `software-team:researcher` was Read/Grep/Glob/WebFetch/WebSearch only, no execution, so it structurally could not do Reproduce (needs to fire real requests) or Hypothesize-then-falsify (needs to add logging and rerun) for anything beyond trivial deterministic bugs — the section's own "(or do them yourself if trivial)" escape hatch doesn't cover the exact non-trivial case debugging methodology exists for. Also fixed the smaller gap the same test found: the spawn template didn't cover researcher's field shape (no Verify with:/Load skill:, Acceptance criteria: means "what findings must establish" not a build outcome) — added a note. A second test on "Unsettled requirements before PLAN" (vague "better notifications" request) passed cleanly but suggested checking whether the current directory is even the right target codebase before drafting product-shaped forks — added as a one-line addition to step 1.
- 2026-08-20: Added `software-team:tdd-builder` (10th agent) — same contract as the general builder, but strictly red (a failing test confirmed to fail for the right reason) -> green (minimum code to pass) -> refactor (tests kept green throughout) per acceptance criterion, reporting the actual red/green trail as evidence. Spawned instead of the general builder whenever the plan calls for TDD, or the task is a bug fix (the regression test from "Debugging before PLAN" is its first red step — wired directly into that section). Verified via a live spawn on a small fizzbuzz task: the RED step on criterion 3 caught a real implementation bug mid-loop (a shadowed branch) before any "final" code was written, confirming tests actually drove the code rather than being retrofitted.
- 2026-08-20: Replaced the tier-only "Model routing" floor table with a difficulty-first scale per user request ("don't fix the model — choose by task difficulty"): mechanical (rename, typo/text fix) -> Haiku, simple/well-understood -> Sonnet, complex/hard (3+ interacting files, concurrency, a real judgment call, a failed round, or any T2 work) -> Opus.
